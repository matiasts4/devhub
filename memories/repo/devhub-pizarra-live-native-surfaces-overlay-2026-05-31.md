- What: Replaced pizarra terminal/browser placeholders with a DOM overlay that projects logical canvas bounds into live TerminalTTY and native browser surfaces, and extracted the native browser lifecycle into reusable hooks.
- Why: Pizarra shapes existed but only rendered Konva rectangles; terminal needed the normal VTE/xterm workspace path and browser needed the existing native GTK bridge instead of iframes.
- Where: src/components/pizarra/PizarraPane.jsx, src/components/pizarra/PizarraCanvas.jsx, src/lib/pizarra/canvasViewport.js, src/components/pizarra/CanvasTerminal.jsx, src/components/pizarra/PizarraLiveSurfaceLayer.jsx, src/components/pizarra/PizarraBrowserSurface.jsx, src/components/workspace/useNativeBrowserSurface.js, src/components/workspace/WorkspaceBrowserPane.jsx.
- Learned: The controlling issue was split viewport ownership: Konva zoom/pan lived locally in PizarraCanvas, so native surfaces had no shared projection math. Moving viewport state into the shared provider made the overlay and native bridge bounds deterministic without touching TerminalWorkspacesManager.
- Follow-up Fix: Added header-based move forwarding for live terminal/browser surfaces, centralized active terminal ownership in PizarraPane so only the most recently interacted terminal receives isActivePanel, and replaced the broken native browser reload catch with a fallback helper that reuses the regular reload path instead of deleted setters.
