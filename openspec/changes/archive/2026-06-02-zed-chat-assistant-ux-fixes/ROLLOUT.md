## Manual smoke checklist

After `pnpm test` is green, run these 6 steps in the dev environment:

1. `pnpm dev` and open the chat panel (right-dock `Zed` tab).
2. Send "abre una terminal" — confirm a new panel becomes visible
   (no manual click on the workspace column needed).
3. Send "ahora corré `ls`" — confirm the assistant uses the SAME
   `session_id` (visible in the devtools Network tab on the
   `POST /api/assistant/chat` body — the `history` field should now
   contain the previous assistant turn and the
   `Tool open_terminal result: {"session_id":"…"}` line).
4. Send "abre https://github.com" — confirm the right-dock browser
   pane navigates AND the system browser also opens (the in-app pane
   is the new path; the xdg-open fallback is preserved).
5. In devtools console, run
   `window.dispatchEvent(new CustomEvent('devhub:zed-open-url', { detail: { url: 'https://example.com', label: 'test' }}))`
   twice — confirm the second dispatch is a no-op (browser pane does
   not re-navigate; this is the BBP-002 idempotence guarantee).
6. Maximize pizarra, then send "abre https://example.com with focus"
   (with `focus: true` in the model output) — confirm pizarra de-maxes
   and the browser tab becomes visible. Without `focus: true`, pizarra
   MUST remain maximized (this is BBP-004 — the opt-in semantics).

## Open questions resolved at apply time

- **Reconciliation between design `rightDockState` and the actual
  `dockState` prop on `WorkspaceBrowserPane`.** The component takes
  `dockState` as a prop (not `rightDockState`). The listener reads
  `dockState?.maximizedView` from props. The dep array tracks
  `dockState?.maximizedView` (not the whole object) so the listener
  re-registers only when the relevant field changes. This is a
  surface-name mismatch from the design but the contract is identical.

- **Design §3.3 internal inconsistency on the `javascript:` URL
  re-validation.** The design's helper code used `if (!payload.url) return;`
  to drop malformed payloads, but that check does NOT catch
  `javascript:alert(1)` (the string is truthy). The task 1.5(c)
  acceptance criterion was that the dispatch MUST be dropped for
  unsafe URLs. The fix is to use `isSafeHttpUrl` to re-validate before
  constructing the CustomEvent, which matches the design's prose
  ("defense-in-depth" / "silently dropped") and the test contract.

- **Pre-existing TWM test failures.** 9 tests in
  `TerminalWorkspacesManager.{split-layout,staleIdentity,counterRandomization}.test.jsx`
  fail on the `feature/session-workspace-restore` baseline BEFORE
  this change. They are unrelated to `zed-chat-assistant-ux-fixes`
  (verified by `git stash` of the apply work and re-running the suite
  — same 9 failures). Out of scope for this change.
