## Deviations From Design

- Route tests already lived beside route files (`src/app/api/agent/execute/route.test.js`, `src/app/api/agent/qa-result/route.test.js`) instead of nested `__tests__` folders; kept project convention rather than relocating files.
- `prepare_agent_workspace` currently provisions `workspace_id`, `reservation_token`, and `correlation_id` over existing `agent_workspaces` rows before deeper executor outcome reconciliation lands in Phase 2/3.
- `devhub_agent_runs` now stays explicitly observer-only for launch metadata: UI projections may retain panel/evidence hints, but executor-reported lifecycle state is ignored in liveness decisions.
- Telegram realtime consumer now suppresses git/worktree verbs in `current_tool` and projects downstream status via `workspace_status` / `evidence_ref` instead.

## Issues / Risks

- `lib/test-schema.js` and `tests/agenthub/mcp/harness.js` needed explicit `agent_workspaces` parity to keep in-memory strict-TDD tests honest; future schema changes must update all three places together.
- The workspace prepare helper still uses `process.cwd()`/default control-plane paths until executor adapters report richer runtime evidence in later phases.
- `report_agent_workspace` now requires correlation alignment with the active preparation attempt; stale retry evidence is rejected until a fresh `prepare_agent_workspace` ack rotates the workspace correlation.
- Repo still has broad unrelated dirty state outside SW-2.2 files; untouched.
- Telegram status API still exposes raw `current_tool`; downstream consumers now intentionally sanitize git/worktree verbs at presentation boundaries rather than mutating the API payload.
