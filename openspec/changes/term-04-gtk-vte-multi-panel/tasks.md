Depends on 1.5, 3.3. **Partial 2026-05-17:** split and close now compute the next active window snapshot synchronously before mutating React state, preventing V1 split columns from being lost on V1↔V2 switches or transferred into the remaining view when a split V1 is closed. Split resize handles now reserve a stronger visible gutter (`w-3`/`h-3`, opaque background, brighter divider) so adjacent native terminals do not visually blend into one surface. **Partial 2026-05-17 (UX active-panel sync):** panel render wiring now passes `onActivatePanel` into each `TerminalTTY`, preserving per-panel overlay controls while making toolbar split buttons follow the last clicked native terminal. **Partial 2026-05-17 (native activation bridge):** workspace state now listens for native `panel-activated` events and updates both `activePanelIds` and the active window snapshot so global split actions follow the most recently focused GTK/VTE panel, not the stale React-side default. **Partial 2026-05-17 (chrome separation):** each split panel now renders a dedicated header/body layout so split/close chrome is outside the native terminal rectangle and remains visible/usable even when GTK is active. **Partial 2026-05-17 (overlay + drag suspension policy):** manager state now centralizes native suspension for the Grid dropdown and internal split-resize drags, then propagates one policy flag to every visible `TerminalTTY` instead of relying on local DOM/z-index patches. **Partial 2026-05-17 (compact floating chrome):** panel chrome now collapses to a short top strip without visible `P#` labels, keeps a floating action cluster anchored top-right, and preserves the separated terminal body contract so GTK/VTE starts higher without reclaiming the controls layer. **Partial 2026-05-17 (true floating overlay pass):** the fixed `h-6` header strip is gone;
