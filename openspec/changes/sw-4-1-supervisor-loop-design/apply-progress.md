### Issues Found

- Root `npm test -- devhub-mcp/tests/integration/tasks.test.js` is filtered out by the root Jest ignore rules for `devhub-mcp/`; focused MCP tests must run from `devhub-mcp/` package path.
- Queue projection was dropping `retry_count` because `buildQueue()` omitted it from pending-task entries; the evaluator now reads the compatibility counter correctly from queue items.
- Snapshot persistence needs the queued task `id` mapped into `task_id`; extracted evaluator helpers now normalize that at the boundary.
- Approval checkpoints were invisible to queue evaluation unless referenced by an existing snapshot key; MCP now falls back to the latest checkpoint by task so first-time approval requests surface without implicit executor progress.
- Approved checkpoints must clear their active gate from future dispatch/read flows; evaluator now nulls the checkpoint key after approval while preserving auditable history on the checkpoint row itself.
- `agentRegistryLive` and `SwarmQueuePanel` were still consuming mixed camelCase/snake_case supervisor mirrors directly; Phase 4 normalized both shapes into the same downstream snapshot contract and strips approval checkpoint internals.
- `SwarmQueuePanel` only handled `queue.items`; Phase 4 broadened the read-model to tolerate MCP-style flat `queue` arrays while preserving legacy payloads.
- Focused verify coverage now locks the frozen pending-approval contract: first read emits `request_approval`, rereads emit `wait` while the same checkpoint remains pending.
- Queue/consumer regressions needed to assert `supervisor` and `supervisor_snapshot` alias parity explicitly so downstream readers do not drift on blocked/orphan states.
- Verify blocker fix: `devhub-mcp/tests/integration/tasks.test.js` was still asserting `request_approval` after `request_supervisor_approval` had already materialized the pending checkpoint snapshot; aligned queue/claim expectations to frozen reread semantics (`wait`).
